# Creative method — independent seeds per creative path under user-led scope

## 1. Start with the user's task, not the glyph

Before any seeds, briefly restate the goal, quantity, genre/domain, compatibility requirements, explicit freedom to redesign, and what success looks like. A fresh image brief, an enterprise UI workflow, and a card mechanic have different relevant innovation spaces. The skill must not pretend all are games.

## 2. Observe characters without importing hidden constraints

`V` suggests convergence, valley, or a sharp sound. `8` suggests repetition, two chambers, vertical symmetry. `X` suggests crossing, comparison, or unknowns. `Q` suggests a closed loop with one exception. Observations should be transformed into ideas *through* a user-relevant axis. If the character does not help, use another reading. A glyph is not permission to introduce a new resource, population system, or control mechanism.

## 3. Change form vs. change mechanism

Use the degrees of freedom stated by the user. When asked for variations, candidates should differ meaningfully in decision, condition, objective, timing, information, interaction or expression. If users only request visual styles, do not impose new gameplay rules. If they request core mechanic redesign, do not limit yourself to colors and names.

## 4. Differentiate novelty and compatibility

A new mechanic can be impressive yet unrelated to the user's needs. Evaluate relevance first; innovation then. Users can explicitly authorize expansion beyond established design: describe costs, data dependencies and potential migration, not blanket rejection. If the user prohibits expansion, creativity must work inside that boundary. Don't turn background into implicit absolute rules.

## 5. Review checklist

- Does every proposal actually serve this user's current objective?
- Are all explicit numeric constraints satisfied?
- Is the diversity meaningful in the requested dimension, not cosmetic?
- Is any random observation being mistaken for a requirement?
- Are new systems/fields proportional to the allowed design scope?
- Is the design compatible with user-specified invariants, with any extensions clearly marked?
- Do explanations distinguish facts, assumptions, hypotheses and implementation requirements?
- Can an evaluator compare/replay a seed brief from seed + spec + version?

## 6. Assessment design

To evaluate the skill rather than a single output, compare matched runs with (a) no seed, (b) one fixed seed, (c) several different seeds, using the *same requirement specification*. Blind-score relevance, constraint compliance, mechanic distinctness and practical utility. High novelty is not automatically a quality increase.

## 7. Design the funnel, not just the random walk

For a multi-idea request, the seed should diversify a **candidate pool**, not directly choose the final products. Reject non-compliant candidates before scoring. Generate initial sketches cheaply and defer detail. Use the requirement evidence, duplication analysis and cross-candidate diversity to decide which possibilities survive. A large random pool is only useful if proposals are real and evaluators are rigorous; 256 superficial variants are not a meaningful search.

## 8. Where this method fits in a complete design job (v1.5)

Random character associations are one *divergent exploration technique*, not a universal design lifecycle. Apply them after framing the actual need and researching the constraints when useful. Before delivering a design, compare alternatives, detail the chosen solution, define acceptance criteria and verify where practical. A seed is not evidence that a design works, and a replayable route does not reproduce design decisions or physical/UX outcomes. For cross-domain workflow and honest verification statuses see `DESIGN_WORKFLOW.md` and `DELIVERY_CONTRACT.md`.

## Independent creative paths (v1.6)

One independent random seed is assigned to exactly one creative exploration route; neither a shared seed nor a route-number salt is a valid substitute. Use a saved manifest to reproduce the entire exploration, including seed-to-route provenance. Evaluating several unrelated seed paths expands search breadth, but it does not guarantee semantic independence of Agent-generated concepts.
